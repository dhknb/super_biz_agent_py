# Redis连接失败告警处理方案

## 告警名称
- **告警名**: `RedisConnectionFailed`
- **告警级别**: 严重
- **触发条件**: Redis连接错误持续3分钟超过20次，或连接成功率低于95%

## 问题描述
当应用无法连接Redis时，可能导致：
- 缓存读写失败
- 会话或状态数据丢失
- RQ任务无法入队或消费
- 接口响应时间明显上升

## 排查步骤

### 步骤1: 获取当前时间
**工具**: `get_current_time`
**目的**: 确定故障发生时间范围，便于后续日志和监控查询

### 步骤2: 查询应用错误日志
**工具**: `query_logs`
**参数要求**:
- **地域**: `ap-guangzhou`
- **日志主题**: `application-logs`
- **时间范围**: 最近15分钟
- **查询条件**: `Redis OR Connection refused OR timeout OR max number of clients reached`

### 步骤3: 查询系统监控指标
**工具**: `query_logs`
**参数要求**:
- **地域**: `ap-guangzhou`
- **日志主题**: `system-metrics`
- **时间范围**: 最近30分钟
- **查询条件**: `service:redis OR port:6379 OR memory_usage:>85`

### 步骤4: 检查任务队列影响范围
重点确认：
- RQ队列是否持续堆积
- 上传文档是否无法进入索引流程
- 是否只有缓存操作失败，还是整条链路异常

## 常见原因分析

### 原因1: Redis服务宕机
**特征**:
- 日志中大量 `Connection refused`
- 所有实例同时报错
- RQ worker与API同时受影响

**处理方案**:
1. 立即确认Redis进程或容器状态
2. 恢复Redis服务并检查启动日志
3. 验证端口6379监听正常
4. 恢复后观察应用是否自动重连

### 原因2: Redis负载过高
**特征**:
- 请求超时增多
- Redis内存或CPU使用率很高
- 慢查询或阻塞命令明显增多

**处理方案**:
1. 检查是否有大Key或阻塞命令
2. 临时扩容或切流
3. 优化热点缓存访问逻辑
4. 调整连接池和超时参数

### 原因3: 连接数耗尽
**特征**:
- 日志中出现 `max number of clients reached`
- 短时间并发请求明显升高
- 部分实例能连上，部分失败

**处理方案**:
1. 查看Redis当前连接数
2. 排查连接泄漏或未及时释放
3. 适当调大最大连接数
4. 重启异常实例释放无效连接

### 原因4: 网络或DNS异常
**特征**:
- 连接超时而不是拒绝
- 跨可用区或跨机房访问失败
- 同一时段其他依赖也有网络问题

**处理方案**:
1. 检查网络连通性和DNS解析
2. 对比不同节点的访问结果
3. 排查安全组、防火墙、服务发现配置
4. 必要时切换备用节点

## 紧急处理措施

### 立即操作（5分钟内）
1. 恢复Redis服务或切换备用实例
2. 确认RQ队列是否恢复收发
3. 对非关键缓存功能进行降级

### 短期措施（30分钟内）
1. 分析报错高峰时间段日志
2. 检查Redis资源使用和连接池状态
3. 修正连接配置、超时和重试策略
4. 处理堆积任务，避免故障恢复后流量放大

### 长期优化
1. 为Redis建立高可用和主从切换方案
2. 完善连接池监控和告警
3. 对RQ链路增加独立可观测性
4. 优化缓存Key设计和热点控制

## 验证步骤
1. 确认Redis连接错误降为0
2. 验证RQ任务可以正常入队和消费
3. 检查核心接口响应时间恢复正常
4. 观察30分钟无再次抖动

## 相关告警
- `RQWorkerStopped`: RQ Worker停止
- `DocumentIndexFailed`: 文档索引失败
- `HighMemoryUsage`: 内存使用率过高
