# DashScope接口失败告警处理方案

## 告警名称
- **告警名**: `DashScopeAPIFailed`
- **告警级别**: 严重
- **触发条件**: LLM或Embedding请求连续5分钟失败率超过20%

## 问题描述
当DashScope接口失败时，可能导致：
- 对话问答失败或返回空结果
- 文档无法生成embedding
- AIOps诊断推理中断
- 知识库上传和检索链路同时受影响

## 排查步骤

### 步骤1: 获取当前时间
**工具**: `get_current_time`
**目的**: 确认外部接口异常开始时间

### 步骤2: 查询应用错误日志
**工具**: `query_logs`
**参数要求**:
- **地域**: `ap-guangzhou`
- **日志主题**: `application-logs`
- **时间范围**: 最近20分钟
- **查询条件**: `DashScope OR embedding OR qwen OR rate limit OR authentication`

### 步骤3: 识别失败类型
重点判断：
- 是认证失败、限流、超时还是服务端错误
- 仅聊天失败，还是embedding也失败
- 是否与单次请求量过大有关

### 步骤4: 评估业务影响
重点确认：
- 前台聊天是否不可用
- 文档索引是否批量失败
- AIOps诊断是否中途终止

## 常见原因分析

### 原因1: API Key错误或过期
**特征**:
- 返回认证失败
- 所有请求立即失败
- 发布或配置变更后开始出现

**处理方案**:
1. 核对 `DASHSCOPE_API_KEY`
2. 检查环境变量是否正确注入
3. 更换有效凭证后重启服务
4. 验证聊天和embedding接口恢复

### 原因2: 外部接口限流
**特征**:
- 高峰期失败增多
- 返回429或频控提示
- 批量索引和高并发聊天同时进行时更明显

**处理方案**:
1. 立即降低并发请求
2. 对批量索引做限速
3. 增加重试退避策略
4. 拆分高峰任务或错峰处理

### 原因3: 网络抖动或请求超时
**特征**:
- 请求偶发超时
- 不同实例成功率不一致
- 同时伴随其他外部依赖网络问题

**处理方案**:
1. 检查出口网络和DNS
2. 适当调高超时阈值
3. 增加失败重试
4. 对关键路径增加降级提示

### 原因4: 请求内容异常
**特征**:
- 仅部分请求失败
- 大文本或特殊字符更容易触发
- embedding批量文档时更明显

**处理方案**:
1. 限制单次请求文本长度
2. 清洗非法字符
3. 将大任务拆分为更小批次
4. 为失败样本记录详细上下文

## 紧急处理措施

### 立即操作（5分钟内）
1. 确认认证、限流或网络故障类型
2. 暂停高并发批量索引任务
3. 对聊天和诊断功能做降级提示

### 短期措施（30分钟内）
1. 修复凭证或网络问题
2. 调整并发和重试策略
3. 重试失败的索引或对话请求
4. 观察错误率是否恢复

### 长期优化
1. 建立外部模型接口成功率监控
2. 对聊天和embedding链路分别告警
3. 建立限流保护与任务削峰策略
4. 优化大文本切分和调用批次

## 验证步骤
1. 确认DashScope调用成功率恢复正常
2. 验证聊天、诊断和embedding都可用
3. 检查失败任务可正常重试
4. 观察30分钟无新增大规模失败

## 相关告警
- `DocumentIndexFailed`: 文档索引失败
- `HighAPILatency`: API延迟过高
- `DependencyCallTimeout`: 依赖调用超时
