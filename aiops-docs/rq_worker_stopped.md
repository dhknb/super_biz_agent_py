# RQ Worker停止告警处理方案

## 告警名称
- **告警名**: `RQWorkerStopped`
- **告警级别**: 严重
- **触发条件**: RQ Worker进程退出，或队列无消费持续5分钟

## 问题描述
当RQ Worker停止时，可能导致：
- 文档上传后长期停留在待索引状态
- 重新索引任务无法执行
- 知识库无法及时更新
- 前台看似上传成功，但检索结果不更新

## 排查步骤

### 步骤1: 获取当前时间
**工具**: `get_current_time`
**目的**: 确认队列停止消费的起始时间

### 步骤2: 查询Worker日志
**工具**: `query_logs`
**参数要求**:
- **地域**: `ap-guangzhou`
- **日志主题**: `application-logs`
- **时间范围**: 最近30分钟
- **查询条件**: `rq worker OR index_worker OR job failed OR traceback`

### 步骤3: 查询Redis相关日志
**工具**: `query_logs`
**参数要求**:
- **地域**: `ap-guangzhou`
- **日志主题**: `system-events`
- **时间范围**: 最近30分钟
- **查询条件**: `redis OR queue OR connection refused OR timeout`

### 步骤4: 评估业务影响
重点确认：
- 队列中积压任务数量
- 失败任务是否集中在某类文档
- API上传是否已返回202但无后续处理

## 常见原因分析

### 原因1: Worker进程异常退出
**特征**:
- 日志中存在未捕获异常
- PID不存在或进程频繁重启
- 队列积压快速增长

**处理方案**:
1. 查看最后一次崩溃日志
2. 修复导致退出的异常
3. 重启Worker并确认持续存活
4. 重试失败任务

### 原因2: Redis连接异常
**特征**:
- Worker日志中有连接Redis失败
- API入队也可能同时失败
- 故障与Redis告警时间一致

**处理方案**:
1. 恢复Redis连接
2. 重启Worker重建连接
3. 检查队列堆积和失败任务
4. 验证新任务可正常消费

### 原因3: 索引任务卡死或执行过慢
**特征**:
- Worker仍在运行，但队列无明显推进
- 单个任务运行时间过长
- 大文件或外部依赖故障时更明显

**处理方案**:
1. 定位卡住的job_id
2. 检查Milvus、DashScope等下游依赖
3. 终止异常任务并重试
4. 优化超时和重试策略

### 原因4: 资源不足导致Worker被杀
**特征**:
- 系统日志中有OOM kill或容器被驱逐
- 高峰期更容易出现
- Worker重启后短时间再次退出

**处理方案**:
1. 检查内存、CPU和磁盘资源
2. 扩容或限速任务消费
3. 降低并发或分批处理
4. 优化大文档索引流程

## 紧急处理措施

### 立即操作（5分钟内）
1. 重启RQ Worker
2. 恢复Redis或下游依赖
3. 暂停批量上传避免继续堆积

### 短期措施（30分钟内）
1. 排查失败job和死循环任务
2. 处理堆积任务并观察消费速度
3. 对失败文档执行重新索引
4. 补充告警和日志定位信息

### 长期优化
1. 为Worker增加守护和自恢复机制
2. 建立队列长度与消费延迟监控
3. 优化大文档索引和失败重试策略
4. 为关键任务增加幂等与补偿流程

## 验证步骤
1. 确认Worker进程稳定运行
2. 验证队列开始持续消费
3. 检查新上传文档能完成索引
4. 观察30分钟无再次停止

## 相关告警
- `RedisConnectionFailed`: Redis连接失败
- `DocumentIndexFailed`: 文档索引失败
- `MilvusUnavailable`: Milvus不可用
