# Milvus不可用告警处理方案

## 告警名称
- **告警名**: `MilvusUnavailable`
- **告警级别**: 紧急
- **触发条件**: Milvus连接失败持续5分钟，或向量写入/检索成功率低于90%

## 问题描述
当Milvus不可用时，可能导致：
- 文档无法完成向量索引
- RAG检索能力失效
- 聊天和诊断结果缺少知识库支撑
- 文档重建索引任务持续失败

## 排查步骤

### 步骤1: 获取当前时间
**工具**: `get_current_time`
**目的**: 确定Milvus异常起始时间

### 步骤2: 查询应用侧Milvus错误日志
**工具**: `query_logs`
**参数要求**:
- **地域**: `ap-guangzhou`
- **日志主题**: `application-logs`
- **时间范围**: 最近20分钟
- **查询条件**: `Milvus OR pymilvus OR vector store OR collection OR timeout`

### 步骤3: 查询基础设施事件日志
**工具**: `query_logs`
**参数要求**:
- **地域**: `ap-guangzhou`
- **日志主题**: `system-events`
- **时间范围**: 最近30分钟
- **查询条件**: `milvus OR etcd OR minio OR restart OR crash`

### 步骤4: 确认故障范围
重点确认：
- 仅索引失败，还是检索也失败
- 是Milvus本身异常，还是依赖MinIO/etcd异常
- 是否只影响新文档，老文档检索是否仍可用

## 常见原因分析

### 原因1: Milvus服务未启动或异常退出
**特征**:
- 连接直接被拒绝
- 所有向量相关操作同时失败
- 容器或进程存在重启记录

**处理方案**:
1. 检查Milvus服务状态
2. 查看容器日志定位启动失败原因
3. 确认端口19530监听正常
4. 恢复后执行连接和检索验证

### 原因2: MinIO或etcd依赖异常
**特征**:
- Milvus连接偶发成功，但写入失败
- 创建collection、flush或load异常
- 周边组件也有重启或报错

**处理方案**:
1. 检查MinIO和etcd状态
2. 修复依赖后重启Milvus
3. 校验collection加载状态
4. 重试失败的索引任务

### 原因3: 向量写入压力过高
**特征**:
- 大批量上传或重建索引时超时
- 写入成功率下降，检索延迟上升
- CPU、内存或磁盘IO较高

**处理方案**:
1. 暂停非必要批量导入
2. 降低并发写入速率
3. 扩容资源或优化索引参数
4. 分批重试失败任务

### 原因4: Collection状态异常
**特征**:
- 检索报collection not loaded
- 部分文档可检索，部分不可检索
- 删除和重建索引后状态不一致

**处理方案**:
1. 检查collection和索引状态
2. 重新load或重建相关collection
3. 校验document_id元数据一致性
4. 对异常文档执行重新索引

## 紧急处理措施

### 立即操作（5分钟内）
1. 恢复Milvus及其依赖服务
2. 暂停批量上传和重建索引
3. 对聊天功能提示知识库可能降级

### 短期措施（30分钟内）
1. 分析失败请求和受影响文档范围
2. 修复collection或依赖服务异常
3. 批量重试失败的文档索引任务
4. 验证检索质量恢复

### 长期优化
1. 为Milvus建立资源和依赖监控
2. 补充向量写入、检索成功率告警
3. 优化批量索引的并发控制
4. 建立数据一致性巡检机制

## 验证步骤
1. 确认Milvus连接恢复
2. 验证新文档可完成索引
3. 验证历史文档可正常检索
4. 观察30分钟无新增Milvus异常

## 相关告警
- `DocumentIndexFailed`: 文档索引失败
- `VectorSearchTimeout`: 向量检索超时
- `ServiceUnavailable`: 服务不可用
