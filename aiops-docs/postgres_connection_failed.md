# PostgreSQL连接失败告警处理方案

## 告警名称
- **告警名**: `PostgresConnectionFailed`
- **告警级别**: 严重
- **触发条件**: 数据库连接失败持续3分钟超过10次，或连接池可用连接数低于10%

## 问题描述
当应用无法连接PostgreSQL时，可能导致：
- 文档列表、索引任务状态无法查询
- 文件上传流程中断
- 索引任务状态无法更新
- 服务可用但核心功能不可用

## 排查步骤

### 步骤1: 获取当前时间
**工具**: `get_current_time`
**目的**: 锁定故障发生区间

### 步骤2: 查询应用数据库错误日志
**工具**: `query_logs`
**参数要求**:
- **地域**: `ap-guangzhou`
- **日志主题**: `application-logs`
- **时间范围**: 最近15分钟
- **查询条件**: `psycopg OR connection pool OR database is unavailable OR too many connections`

### 步骤3: 查询数据库相关系统日志
**工具**: `query_logs`
**参数要求**:
- **地域**: `ap-guangzhou`
- **日志主题**: `system-events`
- **时间范围**: 最近30分钟
- **查询条件**: `postgres OR restart OR crash OR disk full`

### 步骤4: 判断影响范围
重点确认：
- API是否仅部分接口异常
- 文件上传后是否停留在待索引状态
- 是否伴随磁盘、CPU、连接数异常

## 常见原因分析

### 原因1: PostgreSQL实例异常退出
**特征**:
- 所有依赖数据库的接口同时报错
- 日志中有 `connection refused`
- 数据库重启或崩溃事件明显

**处理方案**:
1. 检查数据库进程或容器状态
2. 查看启动失败原因
3. 确认数据目录和磁盘空间正常
4. 恢复数据库后重建应用连接

### 原因2: 连接池耗尽
**特征**:
- 高并发时错误明显增多
- 日志中有等待连接超时
- 数据库本身可访问，但应用报错

**处理方案**:
1. 查看连接池配置和当前连接数
2. 排查慢SQL和长事务
3. 临时扩容连接上限
4. 优化事务边界和连接释放逻辑

### 原因3: 数据库性能下降
**特征**:
- 应用大量超时
- 慢查询明显增加
- CPU、IO或锁等待升高

**处理方案**:
1. 检查慢查询和锁等待
2. 终止异常长事务
3. 优化SQL和索引
4. 必要时扩容实例规格

### 原因4: 磁盘满或数据目录异常
**特征**:
- 数据库写入失败
- 文件上传成功但索引状态无法落库
- 日志中有 `No space left on device`

**处理方案**:
1. 立即清理磁盘空间
2. 检查WAL和日志目录增长
3. 恢复后执行健康检查
4. 评估数据归档和容量规划

## 紧急处理措施

### 立即操作（5分钟内）
1. 恢复数据库可用性
2. 暂停高风险批量操作
3. 必要时切换只读或维护模式

### 短期措施（30分钟内）
1. 修复连接池、磁盘或性能瓶颈
2. 清理或终止异常会话
3. 核对索引任务状态一致性
4. 重试失败的上传或索引任务

### 长期优化
1. 完善数据库高可用方案
2. 建立连接池和慢SQL监控
3. 定期巡检表膨胀、锁等待和磁盘容量
4. 为关键写路径增加降级方案

## 验证步骤
1. 核对数据库连接恢复成功
2. 验证文档列表和上传接口正常
3. 检查索引任务状态能正常更新
4. 观察30分钟无新增数据库连接错误

## 相关告警
- `DatabaseQueryTimeout`: 数据库查询超时
- `DocumentIndexFailed`: 文档索引失败
- `HighDiskUsage`: 磁盘使用率过高
