# 文档索引失败告警处理方案

## 告警名称
- **告警名**: `DocumentIndexFailed`
- **告警级别**: 严重
- **触发条件**: 文档索引任务失败次数连续10分钟超过3次，或单个任务重试后仍失败

## 问题描述
当文档索引失败时，可能导致：
- 新上传知识无法进入知识库
- RAG检索结果缺少最新文档
- AIOps诊断无法参考新增处理经验
- 用户误以为上传成功但实际不可检索

## 排查步骤

### 步骤1: 获取当前时间
**工具**: `get_current_time`
**目的**: 锁定失败任务时间段

### 步骤2: 查询索引任务日志
**工具**: `query_logs`
**参数要求**:
- **地域**: `ap-guangzhou`
- **日志主题**: `application-logs`
- **时间范围**: 最近30分钟
- **查询条件**: `index job OR vector index OR failed OR traceback`

### 步骤3: 关联查询依赖异常
**工具**: `query_logs`
**参数要求**:
- **地域**: `ap-guangzhou`
- **日志主题**: `application-logs`
- **时间范围**: 同上
- **查询条件**: `Milvus OR Redis OR DashScope OR embedding OR timeout`

### 步骤4: 确认失败类型
重点确认：
- 失败发生在入队、切分、embedding还是向量写入阶段
- 是否仅某个文件失败
- 是否与文档大小、编码或内容格式有关

## 常见原因分析

### 原因1: RQ Worker未消费
**特征**:
- 上传接口返回202，但状态长时间不变化
- 队列堆积明显
- Worker日志缺失或异常退出

**处理方案**:
1. 恢复RQ Worker
2. 检查队列积压和失败任务
3. 手动重试失败任务
4. 验证状态回写正常

### 原因2: Embedding调用失败
**特征**:
- 日志中有DashScope或embedding错误
- 切分完成但无法继续写入向量
- 高峰期或网络波动时更明显

**处理方案**:
1. 检查API Key和外部服务可用性
2. 重试失败任务
3. 对大批量任务限流
4. 增加重试和熔断保护

### 原因3: Milvus写入失败
**特征**:
- 文档切分成功，但add_documents失败
- 旧文档检索可能正常，新文档无法入库
- 向量库连接或collection异常

**处理方案**:
1. 恢复Milvus服务
2. 校验collection状态
3. 重试失败文档索引
4. 检查delete和add顺序是否产生空窗

### 原因4: 文档内容异常
**特征**:
- 仅某一类文档失败
- 可能包含编码问题、超长内容或不支持格式
- 同一文件多次重试仍失败

**处理方案**:
1. 检查文件编码和内容完整性
2. 控制文件大小和分片策略
3. 过滤异常字符或非法内容
4. 为失败文件增加更明确的错误信息

## 紧急处理措施

### 立即操作（5分钟内）
1. 确认失败环节并恢复关键依赖
2. 暂停批量上传，避免扩大影响
3. 记录失败文档和job_id

### 短期措施（30分钟内）
1. 重试失败任务
2. 修复Worker、Milvus或Embedding问题
3. 对单个异常文档做隔离处理
4. 验证上传到检索链路恢复

### 长期优化
1. 增强索引链路分阶段监控
2. 为失败任务增加自动重试和补偿
3. 优化错误提示，明确失败位置
4. 建立大文档和异常文档准入规则

## 验证步骤
1. 确认失败任务已成功重试
2. 验证新文档可被检索到
3. 检查文档状态更新为已完成
4. 观察30分钟无新增索引失败

## 相关告警
- `RQWorkerStopped`: RQ Worker停止
- `MilvusUnavailable`: Milvus不可用
- `DashScopeAPIFailed`: DashScope接口失败
