## 一、这天要解决什么问题

告警可能来自不同系统：有人手动填一个 JSON，Prometheus 用它自己的格式推送，
将来还可能接 Zabbix、云监控。它们的字段名千奇百怪：

- 手工填的：`{"alert_name": "HighCPUUsage", "severity": "critical"}`
- Prometheus 推的：`{"labels": {"alertname": "HighCPUUsage", "severity": "critical"}, "annotations": {...}}`

同样是「告警名」，一个叫 `alert_name`，一个藏在 `labels.alertname` 里。

如果后面每个环节（检索、生成报告）都要去应付这些差异，代码会乱成一团。

**解决办法：定义一个统一的标准模型 `AlarmEvent`，所有外部格式先「归一化」成它。**
后面所有代码只认这一个格式。这就像海关：不管你从哪国来，入境后都换成本国身份证。

## 二、先看枚举：把"字符串魔法值"变成受控集合

```python
from enum import StrEnum

class AlarmSeverity(StrEnum):
    """告警级别（统一口径）"""
    CRITICAL = "critical"
    WARNING = "warning"
    INFO = "info"
    UNKNOWN = "unknown"
```

### 逐行讲解

- `StrEnum` 是 Python 3.11+ 的枚举类型，**成员既是枚举又是字符串**。
  `AlarmSeverity.CRITICAL == "critical"` 为真，存数据库/转 JSON 时直接就是 `"critical"`。
- **为什么用枚举而不是直接写字符串？** 如果全项目到处写 `"critical"`，
  哪天手滑写成 `"critcal"`（拼错），Python 不会报错，bug 潜伏到线上。
  用枚举，你写 `AlarmSeverity.CRITICl` 会**立刻**报 `AttributeError`——错误提前暴露。
- 这就是"用类型把错误挡在编译/编辑期"的思想。

同理还有 `AlarmSource`（告警来源）：
```python
class AlarmSource(StrEnum):
    MANUAL = "manual"
    PROMETHEUS = "prometheus"
    ZABBIX = "zabbix"      # 预留，暂未实现
    CLOUD = "cloud"        # 预留
```

## 三、级别映射表：处理"同义词"

不同系统对"严重"的叫法不同：Prometheus 叫 `critical`，Zabbix 叫 `disaster`/`high`。
我们需要把它们都归到统一的 `AlarmSeverity`：

```python
_SEVERITY_ALIASES: Dict[str, AlarmSeverity] = {
    "critical": AlarmSeverity.CRITICAL,
    "crit": AlarmSeverity.CRITICAL,
    "fatal": AlarmSeverity.CRITICAL,
    "warning": AlarmSeverity.WARNING,
    "warn": AlarmSeverity.WARNING,
    "disaster": AlarmSeverity.CRITICAL,   # Zabbix 风格
    "high": AlarmSeverity.CRITICAL,       # Zabbix 风格
    ...
}

def normalize_severity(raw: str | None) -> AlarmSeverity:
    if not raw:
        return AlarmSeverity.UNKNOWN
    return _SEVERITY_ALIASES.get(raw.strip().lower(), AlarmSeverity.UNKNOWN)
```

### 讲解

- 这是一个**查表**：把各种写法映射到统一枚举。
- `raw.strip().lower()`：先去空格、转小写，让 `"Critical "`、`"CRITICAL"` 都能匹配。
- `.get(key, 默认值)`：字典的安全取值——查不到不报错，返回 `UNKNOWN`。
  **这体现了一个原则：遇到不认识的输入，不崩溃，给个安全兜底值。**

## 四、核心模型 AlarmEvent

```python
from pydantic import BaseModel, ConfigDict, Field

class AlarmEvent(BaseModel):
    alert_name: str = Field(description="告警名称，如 HighCPUUsage")
    severity: AlarmSeverity = Field(default=AlarmSeverity.UNKNOWN, description="归一化后的告警级别")
    source: AlarmSource = Field(default=AlarmSource.MANUAL, description="告警来源")

    service: Optional[str] = Field(default=None, description="受影响服务")
    instance: Optional[str] = Field(default=None, description="受影响实例")
    resource_type: Optional[str] = Field(default=None, description="资源类型")
    resource_id: Optional[str] = Field(default=None, description="资源唯一标识")

    metric_name: Optional[str] = Field(default=None, description="触发告警的指标名")
    metric_value: Optional[float] = Field(default=None, description="触发时的指标值")

    summary: Optional[str] = Field(default=None, description="告警摘要")
    labels: Dict[str, str] = Field(default_factory=dict, description="业务/环境标签")

    fired_at: Optional[datetime] = Field(default=None, description="首次触发时间")
    resolved_at: Optional[datetime] = Field(default=None, description="恢复时间，未恢复为空")

    raw_payload: Dict[str, Any] = Field(default_factory=dict, description="原始告警数据")
```

### 逐字段讲解

| 字段 | 类型 | 说明 |
|------|------|------|
| `alert_name` | `str`（必填）| 没有默认值 = 必填，创建时必须给 |
| `severity` | `AlarmSeverity` | 用枚举而不是 str，天然受控 |
| `service`/`instance` | `Optional[str]` | `Optional` = 可以是 None，给人看的定位信息 |
| `labels` | `Dict[str,str]` | `default_factory=dict` = 默认空字典 |
| `raw_payload` | `Dict` | **原始数据全量留档**，出问题能回溯，审计要用 |

### 两个关键写法

**1. `Optional[str]` 是什么？**
```python
service: Optional[str] = None   # 等价于 str | None
```
意思是"这个字段可以是字符串，也可以是 None"。告警不一定都有 service，所以可选。

**2. `default_factory=dict` 为什么不直接写 `default={}`？**
这是 Python 的经典坑！如果写 `default={}`，**所有实例会共享同一个字典对象**，
一个改了别人跟着变。`default_factory=dict` 表示"每次新建实例时调用 `dict()` 造一个新的"，
互不干扰。列表同理用 `default_factory=list`。

## 五、模型里的方法：让数据"会做事"

```python
    @property
    def is_firing(self) -> bool:
        """告警是否仍处于触发状态（未恢复）"""
        return self.resolved_at is None

    def retrieval_query(self) -> str:
        """构造用于 RAG / SOP 检索的查询语句"""
        parts = [self.alert_name]
        if self.service:
            parts.append(self.service)
        if self.summary:
            parts.append(self.summary)
        return " ".join(parts)
```

### 讲解

- `@property` 装饰器：把方法伪装成属性。调用时写 `alarm.is_firing`（不用加括号），
  像访问字段一样。适合"根据现有字段算出来的只读值"。
- `retrieval_query()`：把告警名+服务+摘要拼成一句话，**这句话就是待会儿拿去知识库搜索的查询词**（Day5 会用到）。把这个逻辑放在模型里，是因为"怎么根据告警生成检索词"是告警自己的知识——**数据和它的行为放在一起**，这是面向对象的基本思想。

## 六、归一化函数：外部格式 → AlarmEvent

### 手工格式

```python
def _normalize_manual(payload: Dict[str, Any]) -> AlarmEvent:
    alert_name = payload.get("alert_name") or payload.get("alertname") or "UnknownAlert"
    return AlarmEvent(
        alert_name=alert_name,
        severity=normalize_severity(payload.get("severity")),
        source=AlarmSource.MANUAL,
        service=payload.get("service"),
        ...
        fired_at=_parse_time(payload.get("fired_at") or payload.get("started_at")),
        raw_payload=payload,
    )
```

- `payload.get("alert_name") or payload.get("alertname") or "UnknownAlert"`：
  依次尝试两种字段名，都没有就兜底 `"UnknownAlert"`。`or` 链是 Python 里
  "取第一个非空值"的惯用写法。

### Prometheus 格式（更复杂）

```python
def _normalize_prometheus(payload: Dict[str, Any]) -> AlarmEvent:
    labels = dict(payload.get("labels") or {})
    annotations = dict(payload.get("annotations") or {})

    alert_name = labels.get("alertname") or "UnknownAlert"
    status = (payload.get("status") or "").strip().lower()

    service = labels.get("service") or labels.get("job")
    instance = labels.get("instance")
    # 把已提取的维度从 labels 移除，剩下的才是"业务标签"
    business_labels = {
        k: v for k, v in labels.items()
        if k not in {"alertname", "severity", "service", "job", "instance"}
    }

    resolved_at = _parse_time(payload.get("endsAt"))
    if status == "firing":       # firing 表示还在烧，没恢复
        resolved_at = None

    return AlarmEvent(alert_name=alert_name, ...)
```

### 讲解

- Prometheus 把关键信息藏在 `labels` 里，所以要从 `labels.get("alertname")` 取。
- `business_labels` 那段用了**字典推导式**：遍历 labels，过滤掉已经单独提取的字段
  （alertname/severity/...），剩下的才当作业务标签。避免同一信息存两遍。
- `status == "firing"` 时强制 `resolved_at = None`：Prometheus 用 `endsAt` 的零值
  `0001-01-01T00:00:00` 表示"未恢复"，我们统一转成 None，语义更清晰。

### 分发器：根据来源选归一化函数

```python
_NORMALIZERS = {
    AlarmSource.MANUAL: _normalize_manual,
    AlarmSource.PROMETHEUS: _normalize_prometheus,
}

def normalize_alarm(payload, source=AlarmSource.MANUAL) -> AlarmEvent:
    if isinstance(source, str):
        source = AlarmSource(source.strip().lower())  # 字符串转枚举
    normalizer = _NORMALIZERS.get(source)
    if normalizer is None:
        raise ValueError(f"暂不支持的告警来源: {source.value}")
    return normalizer(payload)
```

### 讲解（这是个重要的设计模式）

- `_NORMALIZERS` 是一张"来源 → 处理函数"的表。
- 新增一种来源（比如 Zabbix），只要写个 `_normalize_zabbix` 函数，往表里加一行，
  **不用改 `normalize_alarm` 本身**。这叫**开闭原则**（对扩展开放，对修改关闭）。
- 这比写一堆 `if source == "manual": ... elif source == "prometheus": ...` 优雅得多。

## 七、时间解析：容错的艺术

```python
def _parse_time(value: Any) -> Optional[datetime]:
    if value in (None, "", "0001-01-01T00:00:00Z"):
        return None
    if isinstance(value, datetime):
        return value
    if isinstance(value, (int, float)):
        return datetime.fromtimestamp(float(value), tz=UTC)  # 时间戳
    if isinstance(value, str):
        try:
            return datetime.fromisoformat(value.strip().replace("Z", "+00:00"))
        except ValueError:
            return None
    return None
```

- 时间可能是：None、空串、Prometheus 零值、datetime 对象、Unix 时间戳、ISO 字符串……
- 这个函数**逐一尝试**，任何解析不了的都返回 None，绝不抛异常。
- `replace("Z", "+00:00")`：Python 的 `fromisoformat` 早期不认末尾的 `Z`（表示 UTC），
  手动替换成 `+00:00` 它才认。这是个常见的兼容处理。

## 八、对应的测试（该看：`tests/unit/test_alarm_event.py`）

测试验证了：
1. 手工格式和 Prometheus 格式**归一化后字段一致**（同一个 alert_name）。
2. 级别别名映射正确（`disaster` → CRITICAL）。
3. 时间解析的各种情况。
4. `retrieval_query()` 拼出的查询词包含告警名和服务。
5. `is_firing` 在 resolved_at 有无时的判断。

**为什么要写测试？** 归一化逻辑很容易在"改一个来源时不小心弄坏另一个"。
有测试，你改完跑一下，绿了就安心，这叫**回归保护**。
