## 1. Python 基础回顾（看代码前必须懂的）

### 1.1 类型注解（Type Hints）

你会看到大量这样的写法：

```python
def add(a: int, b: int) -> int:
    return a + b
```

- `a: int` 意思是"参数 a 应该是整数"。
- `-> int` 意思是"这个函数返回整数"。

**关键：类型注解只是"给人和工具看的说明"，Python 运行时不强制检查。**
写 `a: int` 然后传个字符串进去，Python 不会报错（但类型检查工具如 Pyright 会警告）。

常见注解：

| 写法 | 含义 |
|------|------|
| `str` / `int` / `float` / `bool` | 字符串/整数/小数/布尔 |
| `list[str]` | 元素是字符串的列表 |
| `dict[str, int]` | 键是字符串、值是整数的字典 |
| `str \| None` | 要么字符串，要么 None（`\|` 是"或"）|
| `Optional[str]` | 和 `str \| None` 完全一样（老写法）|
| `Any` | 任意类型（放弃检查）|

### 1.2 装饰器（Decorator）

以 `@` 开头、写在函数/类上面的东西：

```python
@router.post("/aiops")
async def diagnose(...):
    ...
```

`@router.post("/aiops")` 的意思是："把下面这个函数注册成 POST /aiops 的处理器"。
装饰器本质是"一个函数包住另一个函数，给它加功能"。你现在只需理解成"贴标签"。

### 1.3 async / await（异步）

```python
async def analyze(...):
    result = await llm.ainvoke(...)
```

- `async def` 定义的函数叫**协程**，调用时不会立刻执行，要用 `await` 才真正跑。
- `await` 的意思是："这一步可能要等（比如等网络返回），等的时候别干等着，让出 CPU 去干别的"。

**为什么要异步？** 因为 AI 调用、数据库查询、网络请求都很慢（几百毫秒到几秒）。
如果同步等待，一个请求就把整个服务卡住了。异步让服务在等待时能处理别的请求，吞吐量高得多。

打个比方：
- **同步** = 你在餐厅点餐后站在窗口干等，后面的人全堵着。
- **异步** = 你点完餐拿个号找座位坐下，好了叫你，期间服务员能接待别人。

### 1.4 数据类 / 枚举

```python
from enum import StrEnum

class Color(StrEnum):
    RED = "red"
    GREEN = "green"
```

**枚举（Enum）** = "只能取固定几个值的类型"。比如告警级别只能是 critical/warning/info，
用枚举比用字符串安全——写错了 IDE 会提示，不会出现 "criticl" 这种拼写错误。

`StrEnum` 是"同时也是字符串的枚举"，`Color.RED == "red"` 成立，方便存数据库/转 JSON。

## 2. 三大框架（这个项目的骨架）

### 2.1 FastAPI —— Web 框架（负责"接请求、发响应"）

它做的事：把 HTTP 请求（前端发来的）转成 Python 函数调用，再把返回值转成 HTTP 响应。

```python
from fastapi import APIRouter

router = APIRouter()

@router.post("/aiops/alerts/analyze")   # 声明：POST 请求，路径 /aiops/alerts/analyze
async def analyze_alert(request: AnalyzeAlertRequest):
    return {"code": 201, ...}            # 返回的 dict 自动变成 JSON
```

- **APIRouter** = 一组接口的集合，最后挂到主应用上。
- 请求体（JSON）会自动"喂"给函数参数，响应（dict）自动转成 JSON。
- 好处：自动生成 API 文档（访问 `/docs` 就能看到所有接口并在线测试）。

### 2.2 Pydantic —— 数据校验（负责"检查数据长得对不对"）

定义"数据应该长什么样"，Pydantic 帮你校验 + 转换：

```python
from pydantic import BaseModel, Field

class AnalyzeAlertRequest(BaseModel):
    payload: dict          # 必填
    source: str = "manual" # 可选，默认 "manual"
```

如果前端发来的 JSON 缺了 `payload`，Pydantic 自动返回 422 错误，根本不会进你的函数。
**这就是"数据校验前移"——脏数据在门口就被拦下，函数内部拿到的一定是干净的。**

- `BaseModel` = 所有 Pydantic 模型的基类。
- `Field(...)` = 给字段加说明、默认值、约束（如长度限制）。

### 2.3 SQLAlchemy —— ORM（负责"Python 对象 ↔ 数据库表"互转）

**ORM = Object-Relational Mapping（对象关系映射）**。
一句话：让你用"操作 Python 对象"的方式操作数据库，不用手写 SQL。

```python
class ProtocolRecord(Base):          # 一个类 = 一张表
    __tablename__ = "protocol_records"
    id: Mapped[str] = mapped_column(String(64), primary_key=True)
    name: Mapped[str] = mapped_column(String(255))

# 用的时候：
protocol = ProtocolRecord(name="变压器协议")  # 造一个对象
db.add(protocol)                              # 相当于 INSERT
db.commit()                                    # 提交事务
```

- 一个**类**对应一张**表**，一个**对象**对应表里的**一行**。
- `Mapped[str]` + `mapped_column(...)` 定义一个字段（列）。
- 你操作对象，SQLAlchemy 在背后翻译成 SQL 发给数据库。

**为什么用 ORM 而不直接写 SQL？** ① 防 SQL 注入；② 换数据库不用改代码；③ 类型安全。

## 3. 几个关键设计概念

### 3.1 分层架构（api / service / repository / model）

想象一家餐厅：

| 层 | 餐厅类比 | 职责 | 本项目文件 |
|----|---------|------|-----------|
| **api** | 服务员 | 接待客人、传菜、不做菜 | `app/api/*.py` |
| **service** | 厨师长 | 编排做菜流程、决定先后 | `app/services/*.py` |
| **repository** | 仓库管理员 | 只管食材存取，不问怎么做菜 | `app/repositories/*.py` |
| **model** | 食材/菜谱定义 | 定义"数据长什么样" | `app/models/*.py` |

**为什么要分层？** 各司其职，改一层不影响别层。比如换数据库只动 repository，
接口格式变了只动 api，业务逻辑变了只动 service。这叫**关注点分离**。

### 3.2 依赖注入（Dependency Injection, DI）

一句话：**不要在函数内部自己 new 对象，而是从外面"塞"进来。**

反例（耦合，难测试）：

```python
class Service:
    def __init__(self):
        self.llm = ChatQwen(api_key="真key")  # 自己创建，写死了
```

正例（依赖注入，好测试）：

```python
class Service:
    def __init__(self, llm=None):     # 从外面接收
        self.llm = llm or default_llm  # 没传就用默认
```

**好处**：测试时可以塞一个"假的 llm"进去，不用真调 AI（省钱、快、稳定）。
本项目 Day5 的 `FirstResponseService(llm=..., sop_service=...)` 就是这么设计的。

### 3.3 Protocol（鸭子类型的接口）

```python
from typing import Protocol

class Retriever(Protocol):
    def retrieve_documents(self, query: str, top_k: int = 3) -> list: ...
```

Protocol 定义"一个对象需要有哪些方法"，但**不要求它继承自谁**。
只要某个对象有 `retrieve_documents` 方法，它就算是一个 `Retriever`。

这叫**鸭子类型**："如果它走起来像鸭子、叫起来像鸭子，那它就是鸭子"。
好处：测试时随便造个有这个方法的假对象就能替换，不用继承一堆东西。

### 3.4 纯函数

```python
def recall_at_k(retrieved: list, expected: list, k: int) -> float:
    # 只依赖入参，不碰外部状态，同样的输入永远同样的输出
    ...
```

**纯函数** = 给定相同输入，永远返回相同输出，且不产生副作用（不改数据库、不打日志、不动全局变量）。
好处：**极易测试**（给输入断言输出即可），Day8 的评估指标全是纯函数。

## 4. 基础设施名词

### 4.1 Alembic —— 数据库迁移工具

数据库的表结构会变（加字段、改类型）。Alembic 帮你**版本化管理**这些变更：

- 每次改表 = 写一个"迁移文件"（有版本号、有 upgrade/downgrade）。
- `alembic upgrade head` = 把数据库升到最新结构。
- `alembic downgrade` = 回滚。

类比 Git：Git 管代码版本，Alembic 管数据库结构版本。

### 4.2 Redis + RQ —— 异步任务队列

- **Redis** = 一个超快的内存数据库，这里当"任务的中转站"。
- **RQ（Redis Queue）** = 基于 Redis 的任务队列库。

**为什么要队列？** 有些活很慢（比如解析 PDF 要几十秒）。如果让用户在 HTTP 请求里干等，
体验差还容易超时。所以：接口收到请求 → 把活丢进队列 → 立刻返回"收到了"→
后台的 worker 进程慢慢干 → 用户之后再来查结果。

```
用户上传PDF → API立刻返回"任务ID" (202)
                    │
                    ▼ 活丢进 Redis 队列
              worker 进程取出任务 → 慢慢解析 → 存结果
                    │
用户拿任务ID来查 ←──┘
```

### 4.3 SSE（Server-Sent Events）—— 服务器推送

普通 HTTP 是"一问一答"：你发请求，服务器回一次就结束。
**SSE 是"一问多答"**：你发一次请求，服务器可以持续推送多条消息，直到结束。

用在哪：AI 生成很慢，与其让用户等 30 秒看到完整报告，不如**实时推送进度**
（"正在检索…""正在生成…""完成"）。Day9 的诊断时间线就是 SSE。

### 4.4 Milvus —— 向量数据库

存"向量"的专用数据库。**向量**是把文本变成的一串数字（比如 1024 个小数），
语义相近的文本，向量也相近。搜索时不是找关键词，而是找"语义最近"的内容。
这是 RAG（检索增强生成）的核心存储。

## 5. 测试相关

### 5.1 pytest —— 测试框架

```python
def test_add():
    assert add(1, 2) == 3   # assert：断言，不成立就测试失败
```

- 函数名以 `test_` 开头，pytest 自动发现并运行。
- `assert 表达式` = "我断言这个必须为真"，为假就报错。

### 5.2 fixture —— 测试的"预备道具"

```python
@pytest.fixture
def db():
    engine = create_engine("sqlite:///:memory:")  # 造一个内存数据库
    yield session                                  # 交给测试用
    session.close()                                # 测试完清理
```

fixture 是"测试前准备、测试后清理"的工具。用 `yield` 分隔：前面是准备，后面是清理。

### 5.3 mock —— 假替身

**mock** = 用一个"假对象"替换真实依赖，让测试不依赖外部服务。
比如测试时不想真连 AI/数据库，就 mock 一个假的，让它返回预设的固定值。

好处：测试**快**（不等网络）、**稳**（不受外部影响）、**省**（不烧 API 费用）、**安全**（不碰真数据）。
